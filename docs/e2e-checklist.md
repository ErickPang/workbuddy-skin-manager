# WorkBuddy Theme Manager E2E Checklist

该检查会重启本机 WorkBuddy，只在准备发布的 macOS 或 Windows 测试环境中手动执行。两个平台必须分别完成一次完整检查。

1. 确认测试环境安装的是本次待验证的 WorkBuddy `5.2.x` 或 `5.3.x`，并正常启动；确认 Manager 在 Finder / 开始菜单、Dock / 任务栏和应用侧栏中显示同一套清晰图标。
2. 打开 Manager，确认侧栏准确区分“WorkBuddy 已安装”“WorkBuddy 正在运行”和“主题运行中”；若安装版本不在支持范围，应用主题时应收到明确的兼容性错误，而不是静默失败。
3. 在没有活动主题时选择一个有效的自定义 WorkBuddy 安装位置，确认路径和版本更新；选择重命名后的其他 `.app` / `.exe` 应被拒绝，再点击“自动检测”恢复默认检测。活动主题存在且原安装位置失效时，确认可用“重新定位”选回同一 WorkBuddy，恢复状态不会被清除。
4. 进入“从图片生成”，选择一张 PNG、JPEG 或 WebP 背景图，填写主题名称后点击“生成主题并应用”。
5. 进入“我的主题”，确认新主题卡片图片通过本地 asset protocol 正常显示。
6. 确认应用主题前出现重启提示；取消后 WorkBuddy 不退出且主题状态不改变，再次操作并确认后 WorkBuddy 重启、主题生效，顶部状态显示随机 CDP 端口。
7. 在 WorkBuddy 内切换主要页面，确认 shell、主内容区、侧栏和输入区颜色正常；在墨夜和薰衣草之夜主题下发送消息，确认用户消息框背景为暗色且正文清晰可见。
8. 重新加载 WorkBuddy 页面，等待最多 30 秒，确认守护任务重新应用主题；让 WorkBuddy 以普通模式重新启动后，确认 Manager 只提示需要重新应用，不会自动停止或重启 WorkBuddy。
9. 关闭 Manager 主窗口，确认应用只隐藏到菜单栏或系统托盘且主题守护仍工作。
10. 启用“开机启动”，确认系统登录项已注册；使用登录项启动时主窗口不自动出现，手动再次打开 Manager 后已有窗口显示到前台。关闭开机启动后确认登录项被移除。
11. 从“我的主题”导出一个 `.wbskin`，再删除并重新导入，确认名称、配色和背景一致；覆盖已有导出文件时包仍可正常导入。再次导入同 ID 包，以及安装与本地主题同 ID 的预置主题时，确认必须先出现覆盖提示，取消后原主题保持不变。
12. 点击“备份主题库”，确认目标位置新建独立的带时间戳备份目录，目录中每个有效主题各有一个可重新导入的 `.wbskin`，且原有文件未被覆盖；一次选择多个包批量导入，在其中混入一个损坏包，确认其他包继续导入并显示成功、取消、失败汇总。
13. 在测试数据目录中破坏一个非活动主题的 `manifest.json`，重新打开“我的主题”，确认该主题显示为“无法读取”并带原因；恢复后再替换其背景图片，确认图片指纹变化会触发重新校验并再次显示为无法读取。删除后不再显示。不要破坏当前活动主题。
14. 打开“诊断信息”，确认 Manager 版本、平台、WorkBuddy 状态、日志路径和最近错误准确，且复制按钮可用；用键盘打开弹窗，确认焦点进入弹窗，`Tab` 不会移出，`Escape` 可关闭并恢复原焦点。
15. 点击“恢复官方外观”，确认先出现重启提示；确认后 WorkBuddy 以普通模式重启、主题状态被清除。
16. 再次应用主题后选择托盘菜单“完全退出”，确认原生确认框出现，确认后退出前恢复官方外观。
17. 在 WorkBuddy 拒绝正常退出的场景中执行应用或恢复，确认 Manager 在 15 秒后停止操作并提示手动退出，不会强制终止 WorkBuddy。
18. 尝试再次启动 Manager，确认只保留一个实例，并将已有主窗口显示到前台。
19. 在“主题画廊”中安装并应用一个预置主题，确认流程与从图片生成一致；返回画廊后该主题显示“已安装”且不会再次触发覆盖安装。
20. 关闭 Manager 后破坏主设置文件但保留 `.bak`，重新启动并确认自定义安装位置可恢复；写入高于当前版本的设置或状态时，确认应用不直接采用且保留 `.invalid-*` 原文件副本；同时破坏主文件和备份时，确认应用回退默认设置且日志记录恢复原因。
21. 检查 Manager 日志目录中没有新增未处理错误；构造超过 1 MB 的测试日志后，确认旧内容轮转到 `.log.1`，新错误仍能写入当前日志。
22. 用背景图片接近但不超过 8 MB 的图片生成主题，确认不仅颜色生效，主内容区背景也真实显示；主题引擎结果中的 `backgroundPresent` 必须为 `true`，`backgroundImage` 不能为 `none` 或原始 Base64 data URL。
